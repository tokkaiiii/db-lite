# PK 있는 단일 테이블 SELECT *는 셀별로 원본 값을 파일로 다운로드할 수 있게 한다

**Status**: accepted

ADR 0007은 "그리드는 훑어보기용, 전체 값이 필요하면 쿼리를 좁혀서 재조회"를 원칙으로 정하고 별도 기능을 범위 밖으로 뒀다. 이번에 그 원칙을 실제 기능으로 만든다 — 사용자가 디비버처럼 그리드 값이 아니라 DB에 있는 진짜 원본 값을 받고 싶어 했고, 그리드에 표시된 값(ADR 0007/0008로 이미 2000 단위로 잘려 있음)을 그대로 파일로 내보내는 건 "원본 다운로드"라는 이름에 맞지 않기 때문이다.

**지원 범위**는 ADR 0008과 동일하게 `SELECT * FROM 단일테이블 [WHERE ...] [ORDER BY ...]` 형태로 좁히고, 추가로 그 테이블에 **PK가 있을 때만** 지원한다. 다운로드는 "이 행의 이 컬럼 원본 값을 다시 조회"해야 하는데, 임의의 SQL 결과에서 "이 값이 정확히 어느 행에서 왔는지"를 일반적으로 알아낼 방법이 없기 때문이다 — PK 값으로 `SELECT <컬럼> FROM 테이블 WHERE pk1=? AND pk2=? ...`을 다시 실행하는 것이 유일하게 안전한 방법이다. 이 범위 안에서는 잘렸는지 여부와 무관하게 **모든 셀에 동일하게** 다운로드를 제공한다 — "잘린 셀만" 감지하려면 마커 문자열 파싱이 필요한데, 어차피 범위가 이미 안전한 곳으로 좁혀져 있으니 굳이 셀별로 구분할 이유가 없다. 이 요구 때문에 `Result`에 `Table string`과 `PrimaryKey []string` 필드를 추가한다 — ADR 0007 때는 "표시 목적뿐이라 스키마 안 바꾼다"였지만, 이번엔 "행을 재조회로 식별해야 한다"는 새로운 요구라 트레이드오프가 다르다.

**API**: `POST /api/connections/{id}/cell` — 바디로 `{ catalog, table, column, primaryKey: {...} }`를 받아, PK 조건으로 그 컬럼 하나만 다시 SELECT해서 원본 바이트를 `Content-Disposition: attachment`로 직접 응답한다(JSON/base64로 감싸지 않음). Content-Type/확장자는 드라이버가 준 Go 값 타입만으로 단순 구분한다 — `[]byte`는 `application/octet-stream`/`.bin`, `string`은 `text/plain`/`.txt`. 컬럼의 실제 XML/JSON 등 타입을 들여다보고 확장자를 맞추는 건 하지 않는다(범위 밖 — 아래 참고). 클라이언트는 로그인 토큰을 `Authorization` 헤더로 보내므로(쿠키 아님) 순수 `<a href>` 다운로드 링크는 인증이 안 된다 — `fetch()`로 헤더를 붙여 받은 응답을 `Blob`으로 만들고 숨긴 `<a download>`를 코드로 클릭해 저장한다. 권한 검사와 Audit Log 처리는 기존 조회(SELECT) 실행과 동일하게 다룬다 — 최소 읽기 Permission만 있으면 되고, SELECT류는 Audit Log Entry에 기록하지 않는다(CONTEXT.md).

**범위 밖**: 디비버 스타일의 인앱 값 뷰어(Binary/JSON/Text/XML 포맷 전환, Word Wrap, 인코딩 선택)는 이번 결정에 포함하지 않는다. 이번엔 "다운로드"까지만 다루고, 뷰어는 필요성이 확인되면 별도로 다룬다.
