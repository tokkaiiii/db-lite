# Catalog 선택은 서버 상태가 아니라 요청마다 넘기는 값으로

MySQL/Postgres/MSSQL은 하나의 Connection 안에 여러 데이터베이스(Catalog)가 있을 수 있어, 사용자가 화면에서 어느 Catalog에 붙을지 고를 수 있어야 했다. "활성 Catalog"를 서버가 세션으로 기억하는 방식과, 쿼리 실행 요청마다 `catalog` 필드를 같이 보내는 방식을 저울질했다.

서버는 원래부터 쿼리 실행마다 `dbconn.Open`으로 새 연결을 열고 바로 닫는 완전 무상태 구조였고, 커넥션 풀이나 세션도 전혀 없다. Catalog에 세션 상태를 도입하면 이 구조 전체를 바꿔야 하는데, Catalog는 결국 "이번 쿼리를 어느 DB에 붙여서 실행할지"에 불과하므로 요청마다 같이 보내는 쪽을 택했다. 클라이언트는 이를 URL 쿼리 파라미터(`?catalog=`)로 들고 있어 새로고침/공유해도 유지된다.
